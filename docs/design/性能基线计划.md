## 2. 公认基准数据集（回答"是否有"：有，且成熟）

| 基准 | 形态 | 适配 dendro 的理由 | 装载难度 |
|------|------|--------------------|----------|
| **ClickBench** | 单大表（hits.csv ~100 列 / 1 亿行可缩样）+ 100+ 查询 | 扫描/过滤/聚合/排序/TopK 全覆盖；单 CSV 装载最简；ClickHouse/DuckDB/PG 全都报数，业界可比 | 低（缩样 1-10M 行即可起步） |
| **JOB**（Join Order Benchmark，Leis 2015） | IMDB 数据集 21 表 + 113 查询 | **CE/join ordering 的标准试金石**——直接检验 ANALYZE/MCV/直方图/join_est 的实战效果 | 中（IMDB 文件下载 + FK 装载） |
| TPC-H | 8 表 22 查询（dbgen 生成） | 通用 OLAP 对照；DBGEN 生成需一步（可用 duckdb CLI 生成后导 CSV） | 中 |
| TPC-DS | 24 表 99 查询 | 最复杂；嵌入式小引擎普遍不跑，暂不取 | 高 |
| TPC-C / sysbench-oltp | TP 事务面 | A5（谓词冲突位）等 TP 任务用；AP 基线阶段暂缓 | 中 |

**选型结论**：基线对 = **ClickBench（缩样起步）+ JOB（33 查询子集起步）**；
TPC-H 作可选第三件；TP 侧基线在 A5 立项时另建。

## 3. 基线工作流（A 类任务强制门）

```
① 装载器前置（一次性）：
   dendro-server 加 bench-load 子命令（CSV → 多行 VALUES 分块 INSERT；
   现无 COPY——bend_pair 的 1000 行/块模式已验证，扩成通用装载器）
② 基线建立（main 分支，一次性 + 每次合批前可重跑）：
   load ClickBench(1M/10M 两档) + JOB(33) → bench-pair 协议跑全查询
   （预热/配对交替/中位数/愚弄率）→ 数字 + 愚弄率入 docs/bench/baseline-*.md
③ 分支重构：git branch perf/<任务名>；重构期间 main 冻结该模块
④ 对比分析：同数据同协议重跑 → 逐查询 ratio + 全局愚弄率；
   差异 >5% 的查询逐个归因（计划文本 diff + est/actual 变化）
⑤ 合并条件：无 >5% 回退（或回退项有书面归因与接受理由）+ SLT 全过
   + clippy 0 + 差分轴全绿
```

**与既有纪律的衔接**：③-⑤ 的度量全部走 bench_pair（愚弄率纪律，
qorl 调研 P0）；单查询归因用 EXPLAIN ANALYZE est/actual + 计划方言
diff（golden 机制现成）。

3. A 类按"评估 §7.1"的 P1/P2 优先级与真实负载信号逐个走三步门。
