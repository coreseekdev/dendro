# 设计评审 Checklist

> 沉淀自账本/审计轮次与外部调研（S3 WAL 调研 P1-5 起草）。
> 新设计（存储/GC/并发/恢复路径）评审时逐条过；每条都对应一次
> 已发生的事故或已证实的竞态，不是理论洁癖。

## 存储与 GC

1. **时间戳不得做回收下界**（Buffer EnableGC 反例）：对象先写、
   清单后入队的两步提交下，按对象时间戳定 GC floor 会把**在途合法
   对象**当垃圾删（w1 写 ts1 未入队、w2 写 ts2 先入队、GC 以 ts2 为
   floor 删 ts1 的完整 trace 见 s3-wal-collection `opendata/Buffer_notes.md`）。
   正解：单调确认点（入队序/版本号）做 floor；宽限期只是补丁。
   dendro 现行设计均以 manifest 版本/covered_seq 为界——任何新回收
   路径引入 `expires_at`/对象时间戳判定时必须过此条。
2. **不删被引用对象**：墓碑登记与"新版本停止引用"必须是同一个
   manifest 版本的一次原子 PUT（GC 定案不变式 1）。
3. **围栏/线索对象保留**：编码序号高水位的对象（fence 租约 = epoch
   高水位）在主体存活期永不回收；删除让序号回退 = 两个体同代
   （SlateDB "FENCE 对象永不删" 同构，见 GC 定案不变式 5）。
4. **覆盖写会复活已删对象**：任何对"可能已被 GC 的路径"的覆盖 PUT，
   必须写后校验（PUT 成功 ≠ 语义有效）——权威读回 + 死路径撤销 +
   本端终态化（FENCED/poisoned）。参考 `LeaseKeeper::renew_if_due`。

## 并发与恢复

5. **条件写成功不等于语义成功**：陈旧写者的条件写可以"成功"落在
   已被回收的地址上——关键写（领权/围栏/发布）后必须重新校验
   （SlateDB 三个 validate-before / OSWALD 写后校验同构）。
6. **失败终态要显式**：结果未知（网络超时/上传失败）后不得叠加写
   ——毒化（40003 强制重开）而非继续；失势写者终态化（FENCED）
   而非重试抢回。
7. **恢复完整性的可判形式**：设计文档必须给出两条不变量的本地判定
   ——前缀性（已安装集 ⊆ 写历史前缀）与可重建性（头 + 存活日志 +
   物化提交 ⇒ 重建内存态），并落为 debug/test 断言
   （`replay_branch` 末端 + `reopen_rebuilds_identical_state`）。
8. **尾段撕裂与真腐坏分账**：不可变追加物的最后一段损坏按撕裂
   容忍（回放 durable 前缀），非最后段损坏严格报错——两类合同
   不得混同（wal.rs `segment_closed` 语义）。

## SQL 层

9. **单一语义面**：同一查询形状不得存在两条可执行路径（AST/计划
   双路径曾使差分"错 vs 同错"——SQL 层架构审视 §6 全程教训）；
   新算子一律进计划 IR（自足 + 可打印 + 可回 parse）。
10. **递归有界**：用户输入驱动的递归（表达式深度/CTE 迭代）必须有
    显式上限并响亮报错，不得静默截断（RECURSIVE_MAX_ITER/ROWS 口径）。

## 评审流程

- 每条 checklist 项在设计文档中要么满足、要么显式声明豁免理由；
- 新增回收/并发机制时，同步补"事故 ↔ 回归测试"对照行（GC 定案 §6 式）。
