# ADR 决策记录

> 格式：背景 → 决策 → 理由 → 重开条件。重开条件是合同的一部分：
> 没有写重开条件的决策不允许被悄悄推翻。

## ADR-1 单逻辑 IR + 放置属性（vs 双引擎 / 双 IR）

- **背景**：TP/AP 数据量级悬殊（TP 可能 < AP 的 1/10），且读取路径已有
  三层雏形（try_ap_scan 的 CBF 段 + memtx overlay + 事务 overlay）。
- **决策**：一个逻辑 IR；TP/AP 差异表达为 Scan 节点的 placement 属性与
  coverage 区间，不设两套 IR、不设两个引擎。
- **理由**：双引擎（TiFlash/HeatWave/AlloyDB 模式）带来副本同步、一致性
  口径、双倍运维，正是命题拒绝项；coverage 推理让派发可测试（纯函数）。
- **重开条件**：无（这是命题级决策，推翻等于推翻产品定位）。

## ADR-2 执行表示 = push 批管线（vs VDBE 寄存器字节码 vs Volcano）

- **背景**：三个候选——VDBE 式寄存器 VM（SQLite/Turso）、Volcano 逐行
  迭代（MySQL/PG 主流）、push 批式向量化管线（DuckDB/ClickHouse/Velox/
  Polars 四引擎收敛）。
- **决策**：push 批管线（ChunkPlane）。**dVBE 全线取消**（父文档 §7/§8
  归档）；Volcano 不取，LIMIT/EXISTS 短路由由 Sink 断流实现。
- **理由**：四引擎收敛点是行业证据；TP/AP 差异是放置问题不是执行模型
  问题；单算子库使 SIMD 优化一处受益两处；点查用退化管线保延迟。
- **重开条件**：TP 点查 p50 相比现状劣化 >30% 且优化 chunk 池后仍不达
  85% 验收线，或产品进入与 SQLite 正面竞争的亚微米场景。

## ADR-3 标量层 = ScalarStep 步列表（vs AST 直释）

- **背景**：v2a 计划缓存是纯 AST，执行期仍重复名字解析与 AST 遍历。
- **决策**：prepare 期把 Expr 编译为步列表（PG11 EEOP 同构）：列绑定
  （AST 无列索引）、常量池、控制流拍平、常量折叠在编译期完成。
- **理由**：PG 十年生产验证的同构机制；编译期跑优化规则一次而非每次
  执行；步列表可序列化（prepared 语句/EXPLAIN 共用）。
- **重开条件**：无（方向性）；实现细节见 03 号 spec。

## ADR-4 执行 Chunk v1 = RecordBatch 薄包装 + selection（vs 自研可变向量）

- **背景**：DuckDB 的性能优势部分来自可变、可复用的执行向量；arrow-rs
  RecordBatch 不可变、逐算子分配。
- **决策**：v1 的 Chunk 类型是**接口**（列式、带 selection、schema 稳定），
  实现包装 RecordBatch（借用切片，零拷贝来自 CBF 解码产物）+ selection；
  **线程本地缓冲池推迟到 profiling 要求时**，藏在同一接口后。
- **理由**：AP 现状（200k 行聚合 185ms）瓶颈不在分配；点查走退化管线
  不产生中间 Chunk——自研可变向量的复杂度在没有证据前不付。
- **重开条件**：profiling 显示算子间分配进入 TP 点查 p50 前 3 名，
  或 AP 吞吐目标（见 08）不达且分配是热点。

## ADR-5 行为等价迁移（强制派发差分）

- **决策**：提供调试开关 `SET dendro.force_source = delta|main|prolly|
  fallback|auto`，同一 SQL 可强制走任一数据源。I-H1 差分测试升级为：
  测试语料 × 全路径两两对拍。**这是 v2b/v2c-1 的主护舷**。
- **理由**：等价性不能靠"看起来对"；强制派发把内部路径变成可枚举的
  测试维度。该开关仅 debug 构建/测试可用（生产不暴露，S-3 精神）。

## ADR-6 明确不做清单（含重开条件）

| 不做 | 理由 | 重开条件 |
|------|------|---------|
| LLVM/表达式 JIT | PG 经验：OLTP 编译延迟吞收益；等价物是 eval_chunk 向量化 | AP 表达式占 profile >20% 且向量化不足 |
| Cascades/Memo 优化器 | 需求=规则级；先算子后优化器 | join 数 ≥6 的生产负载出现 |
| 等式饱和（egg） | 研究 SOTA，e-graph 爆炸成本 | 同上且规则空间爆炸可测 |
| 跨层 join（Delta×Main） | v1 限制同层，跨层落 RowFallback | v3（hash join + GatherBatch 设计后）|
| 多列 pk 的 Main 路径 | col_segments pk_min/max 单列序（v1 边界） | 段级多列 min/max 设计完成 |
| learned/统计代价模型 | 无工作负载统计基础设施 | 生产负载采样就绪 |
