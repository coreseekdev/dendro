# 10 绑定与名字解析

> 评审 P1-2 补充：三类 FROM 对象没有 TableId、不经过 resolve_table，
> 绑定层必须前置处理；列名解析的 lenient 回退必须原样保留。

## 1. 绑定前置特判清单

| FROM 对象 | 现状机制 | IR 化处理 |
|----------|---------|----------|
| **视图** | manifest.views 存查询文本；展开深度上限 8；基表优先；视图上 AS OF 显式拒绝（R6 P0 教训）| 绑定期展开（递归绑定至基表），深度上限与拒绝语义逐字保留；展开产物是普通 PlanNode 子树（不引入 View 节点——v1 最小）|
| **派生表** `FROM (SELECT ..)` | TableFactor::Derived 递归 eval_query | `Subquery(Box<PlanNode>)` 节点（02 §1）；列名 = 派生表别名作用域 |
| **系统伪表** | table_scan 硬编码：branches / pg_tables / pg_columns / pg_settings / commit_log | `PseudoSource` 枚举进 Source 层（04），**不走派发器**（恒直产 chunk）；专属错误语义保留（伪表上 time travel 报 not_supported）|

## 2. 列名解析（col_lookup 合同）

- 精确匹配（含限定名 `t.col`）优先；
- **lenient 回退原样保留**：`ends_with` 模糊匹配（JOIN 后未限定列名
  靠它解析）——曾因收紧触发回归（见 git 史），**任何 IR 化不得改变
  其匹配序与优先级**；
- 歧义（多表同名列未限定）：现状报 ambiguous——保留；
- ColId 分配：绑定器局部递增；L2 命中时由缓存保证稳定（02 §5-2）。

## 3. 别名作用域

- SELECT 别名可在 ORDER BY 引用（现状 apply_order 支持）；HAVING 可
  引用组键文本（agg.rs 受限形式）——绑定器把这两种引用解析到对应
  ColId/ExprRef，**求值受限性由算子合同保留**（不是绑定的职责）；
- 派生表别名屏蔽内部列名（作用域栈，绑定器维护）。

## 4. 实现前必须回答

1. 视图展开产物是否记入 L2 缓存（展开后 SQL 体积放大）？建议：缓存
   绑定产物即缓存展开结果（这正是 L2 的价值）；上限条款（06 §4）防
   深层嵌套视图撑爆。
2. PseudoSource 的输出 schema 稳定性：pg_columns 等的列集是否可能随
   版本变化？文本 IR 的 table 节点如何表示伪表（建议 `pseudo "pg_columns"`）？
