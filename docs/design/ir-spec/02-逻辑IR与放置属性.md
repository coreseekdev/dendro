# 02 逻辑 IR 与放置属性

## 1. 计划节点

```rust
pub struct PlanNode {
    pub kind: NodeKind,
    pub children: Vec<PlanNode>,        // v1 用所有权 Vec；Arc 化推迟到需要 memo
    pub attr: NodeAttr,
}

pub enum NodeKind {
    Scan(ScanReq),
    Filter(PredId),                     // PredId → ScalarProgram（见 03）
    Project(Vec<ExprRef>),              // 投影表达式（可为计算列）
    Join(JoinKind, PredId),
    Aggregate { groups: Vec<ColId>, aggs: Vec<AggCall> },
    Sort { keys: Vec<(ColId, bool)>, limit: Option<u64> },
    Limit(u64),
    Values(Vec<Vec<SqlValue>>),         // SELECT 1 等常量查询
}
```

`NodeAttr`（属性束——每字段对应一种派发/改写能力，§6.4 结论）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `schema` | `Vec<(ColId, Ty)>` | **ColId = 查询内唯一列号**。所有谓词/投影引用 ColId，物理化时才映射为列偏移——改写不漂移 |
| `placement` | `Vec<ScanAlt>`（仅 Scan 节点） | 物理替身集合（见 §3） |
| `snapshot` | `u64` | gap-free watermark ts；跨层合并的一致性依据 |
| `txn_head` | `Option<root>` | 显式事务冻结根（Q-14 语义） |

**明确不进属性束**：统计信息（进 catalog 带版本）、执行细节（内存布局/
调用约定）、编码方式（CBF footer 私事）。

## 2. 值格与类型

- 逻辑类型 = 现有 `Ty`（types.rs：Null/Bool/Int32/Int64/Float64/Utf8/
  Bytes/Date32/TimestampMs）。**不新增类型**；SQL 类型→Ty 的映射沿用
  translate_columns。
- 比较与运算语义 = 现有 eval.rs 语义（含 collation 现状 = 二进制序）。
  **v2b 不改任何运算语义**（行为等价红线）；collation 升级是独立课题。

## 3. Scan 的物理替身（ScanAlt）

```rust
pub enum ScanAlt {
    /// memtx 点查（pk 等值集）
    DeltaPoint { table: TableId, keys: PkSet },
    /// memtx 范围（pk 区间）
    DeltaRange { table: TableId, range: PkRange },
    /// CBF 段扫描（zone map 剪枝后段集）
    MainScan { table: TableId, segs: Vec<SegId> },
    /// Main + memtx 尾巴归并（现 try_ap_scan overlay 语义）
    MainPlusDelta { table: TableId, segs: Vec<SegId>, tail: TailRange },
    /// prolly 时间旅行/分支点读
    HistoryScan { table: TableId, as_of_root: String },
    /// 现行表扫描（小表/兜底/不支持谓词）
    RowFallback { table: TableId },
}
```

每个 ScanAlt 自带 **coverage 区间**（对该表可见 ts 的覆盖）与**适用谓词
形状**，由派发器消费（见 05）：

| ScanAlt | coverage | 谓词形状要求 |
|---------|----------|-------------|
| DeltaPoint | Full（当前可见集） | pk 等值 |
| DeltaRange | Full | 单列 pk 范围 |
| MainScan | Partial [ckpt_lo, ckpt_hi] | 任意（剪枝程度不同）|
| MainPlusDelta | Full | 单列 pk（v1 边界，见 ADR-6）|
| HistoryScan | Point(as_of) | version 子句 / AS OF |
| RowFallback | Full | 任意 |

## 4. 绑定（AST → 逻辑 IR）

- 名字解析发生在**绑定阶段**：表名 → TableId、列名 → ColId。绑定产物
  可缓存（见 06 的二级缓存），键含 catalog_version。
- 绑定失败（表/列不存在）在此阶段报错，与现语义一致。
- version 子句（AS OF）：`version.is_some()` 时 ScanAlt 集合**只含
  HistoryScan**（R6 P0 门控的 IR 化——不是"剔除"，是"从未加入"）。

## 5. 实现前必须回答

1. `NodeKind::Project` 的表达式（计算列）在 v1 是否允许出现在 Scan
   之上任意位置，还是仅允许 Filter 下推 + 末端 Project？（建议：仅末端
   Project + Filter 谓词内表达式，复杂表达式投影 v1 落 RowFallback 上
   的旧路径——缩小等价性风险面。）
2. ColId 分配器：绑定器局部递增即可，还是需要稳定化以支持缓存？（建议：
   绑定缓存命中的 ColId 由缓存保证稳定，miss 时重新分配——无需全局稳定。）
