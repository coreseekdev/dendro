# 02 逻辑 IR 与放置属性

## 1. 计划节点

```rust
pub struct PlanNode {
    pub kind: NodeKind,
    pub children: Vec<PlanNode>,        // v1 用所有权 Vec；Arc 化推迟到需要 memo
    pub attr: NodeAttr,
}

pub enum NodeKind {
    Scan(ScanReq),
    Filter(PredId),                     // PredId → ScalarProgram（见 03）
    Having(PredId),                     // 聚合后过滤（受限求值形式，见注）
    Project(Vec<ExprRef>),              // 投影表达式（可为计算列）
    Join(JoinKind, PredId),
    Aggregate { groups: Vec<ExprRef>, aggs: Vec<AggCall> },

        // AggCall = {func, arg: Option<ExprRef>, distinct, is_star,
        //            display}（对齐 agg.rs 真实五元组）
        // 算子合同须保留：无分组+空输入 ⇒ 全局聚合仍出一行；
        // 组输出顺序 = 首见序；组键哈希 = to_text（含 NULL/'' 碰撞怪癖）
    Sort { keys: Vec<SortKey>, limit: Option<u64> },
        // SortKey = {expr: ExprRef, desc}：支持序数/别名/未投影列/
        // 任意表达式；NULL 定序怪癖保留（ASC null-last，DESC null-first
        // ——reverse 连 null 位一起翻）；Sort 允许位于 Project 之下
        // 引用输入列（现状 apply_order 语义）
    Limit { offset: u64, limit: u64 },  // 现状支持 OFFSET；pushdown_limit
                                        // = limit+offset 早停语义保留
    Values(Vec<Vec<SqlValue>>),         // SELECT 1 等常量查询
    Subquery(Box<PlanNode>),            // FROM (SELECT ...) 派生表（评审 P1-2）；
                                        // 携带 provenance 注记（来源视图名+深度，
                                        // EXPLAIN 可见——比 PG 还友好；为将来

    // 是参照——评审 O7，实现前 NodeKind 保持封闭）
}

`NodeAttr`（属性束——每字段对应一种派发/改写能力，§6.4 结论）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `schema` | `Vec<(ColId, Ty)>` | **ColId = 查询内唯一列号**。所有谓词/投影引用 ColId，物理化时才映射为列偏移——改写不漂移 |
| `placement` | `Vec<ScanAlt>`（仅 Scan 节点） | 物理替身集合（见 §3） |
| `snapshot` | `u64` | gap-free watermark ts；跨层合并的一致性依据 |
| `txn_head` | `Option<root>` | 显式事务冻结根（Q-14 语义） |

**明确不进属性束**：统计信息（进 catalog 带版本）、执行细节（内存布局/
调用约定）、编码方式（CBF footer 私事）。

## 2. 值格与类型

- 逻辑类型 = 现有 `ColType`（types.rs；SqlValue 才有 Null 变体）。
  **不新增类型**；SQL 类型→ColType 映射沿用 translate_columns。
- **结果 schema 推断保留数据依赖**（评审 P2）：现状结果列类型按数据
  推断（infer_type，空表回退 Utf8）——静态 NodeAttr.schema 只做内部
  绑定，wire 输出类型仍按数据推断，避免空结果类型漂移。
- 比较与运算语义 = 现有 eval.rs 语义（含 collation 现状 = 二进制序）。
  **v2b 不改任何运算语义**（行为等价红线）；collation 升级是独立课题。

## 3. Scan 的物理替身（ScanAlt）（评审 P0-2 修正命名与构成）

**修正**：当前读 ≠ memtx-only。现状点查 = memtx → 墓碑判定 → prolly
当前树 → 事务自身写 四段合成（scan.rs build_point_view 1258-1297）；
checkpoint 截断后**树是点查主数据源**。DeltaPoint/DeltaRange 更名
CurrentPoint/CurrentRange，定义为"当前读"而非"memtx 读"：

```rust
pub enum ScanAlt {
    /// 当前读点查：memtx get → 墓碑判定（latest_ts ≤ snapshot 则
    /// 不得回树）→ prolly lookup → txn writes（四段缺一不可）
    CurrentPoint { table: TableId, keys: PkSet },
    /// 当前读范围：prolly range_scan + snapshot_rows_in_range + txn
    /// （现状不存在"纯 memtx 范围"路径——table_scan 1611-1656）
    CurrentRange { table: TableId, range: PkRange },
    /// CBF 段扫描（zone map 剪枝后段集）
    MainScan { table: TableId, segs: Vec<SegId> },
    /// Main + 当前读尾巴归并（现 try_ap_scan overlay 语义）
    MainPlusDelta { table: TableId, segs: Vec<SegId>, tail: TailRange },
    /// prolly 时间旅行/分支点读
    HistoryScan { table: TableId, as_of_root: String },
    /// 现行表扫描（小表/兜底/不支持谓词）——等价性锚点
    RowFallback { table: TableId },
}
```

| ScanAlt | coverage | 谓词形状要求 |
|---------|----------|-------------|
| CurrentPoint | Full（当前可见集） | pk 等值 |
| CurrentRange | Full | 单列 pk 范围 |
| MainScan | Partial [ckpt_lo, ckpt_hi] | 任意（剪枝程度不同）|
| MainPlusDelta | Full | 单列 pk（v1 边界，见 ADR-6）|
| HistoryScan | Point(as_of) | version 子句 / AS OF |
| RowFallback | Full | 任意 |

**Source 合同必含墓碑判定**（R7-1 伴生语义，曾出 P0）——04 §4 逐段
搬运，不允许"搬运"二字带过。

## 3.5 绑定前置特判（评审 P1-2）

三类 FROM 对象没有 TableId、不经过 resolve_table，绑定层须前置处理
（详见 10 号 spec）：**视图**（manifest.views 查询文本，深度上限 8、
基表优先、AS OF 显式拒绝——R6 P0 教训）；**派生表**（TableFactor::
Derived 递归 eval_query → Subquery 节点）；**系统伪表**（branches/
pg_tables/pg_columns/pg_settings/commit_log，带专属错误语义如伪表上
time travel 报 not_supported）。列名解析的 lenient 回退（col_lookup
ends_with 模糊匹配）原样保留。

## 4. 绑定## 3.6 required_cols 位图（评审 M5a，SQLite colUsed 同构）

ScanReq 增 `required_cols: FixedBitSet`——绑定期从谓词 + 投影并集
推导；CbfSource 只解码命中列（**列存引擎的第一收益**，语义零变化，
纯性能，v2c-1 显式收益项）；RowFallback/Current 路径 v1 忽略之
（行解码本来全列）。

## 4. 绑定（AST → 逻辑 IR）

- 名字解析发生在**绑定阶段**：表名 → TableId、列名 → ColId。绑定产物
  可缓存（见 06 的二级缓存），键含 catalog_version。
- 绑定失败（表/列不存在）在此阶段报错，与现语义一致。
- version 子句（AS OF）：`version.is_some()` 时 ScanAlt 集合**只含
  HistoryScan**（R6 P0 门控的 IR 化——不是"剔除"，是"从未加入"）。

## 5. 实现前必须回答

1. `NodeKind::Project` 的表达式（计算列）在 v1 是否允许出现在 Scan
   之上任意位置，还是仅允许 Filter 下推 + 末端 Project？（建议：仅末端
   Project + Filter 谓词内表达式，复杂表达式投影 v1 落 RowFallback 上
   的旧路径——缩小等价性风险面。）
2. ColId 分配器：绑定器局部递增即可，还是需要稳定化以支持缓存？（建议：
   绑定缓存命中的 ColId 由缓存保证稳定，miss 时重新分配——无需全局稳定。）
