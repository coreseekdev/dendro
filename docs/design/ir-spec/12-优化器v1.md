# 12 优化器 v1（O-1：合取拆分下推 + 规则框架）

> 大阶段（v2 四方向收口）后的优化器第一步。定位：**把散点优化收进
> 显式框架**，落地第一条计划级规则（谓词下推），全程差分可验证。
> 优化器不改语义——每条规则都在"结果等价"合同下工作。

## 0. 现状盘点（O-1 前的散点优化）

| 已有机制 | 位置 | 性质 |
|---------|------|------|
| 表达式常量折叠 + 布尔简化 | sql/optimize.rs（WHERE 专用，scan.rs:332） | 表达式级 |
| 常量谓词短路（Q-1） | eval_select：无列引用谓词单次求值 | 语句级特判 |
| LIMIT/OFFSET 下推 | eval_select → pushdown_limit（无条件/无 join/无聚合时） | 计划级 |
| pk 等值/IN 点查下推 | try_pk_pushdown（dispatch CurrentPoint） | 计划级 |
| pk 范围提取 | extract_pk_range → AP 段剪枝 | 计划级 |
| ScalarStep 编译期折叠 | scalar.rs Ctx（truncate 死码） | 标量级 |

共同点：各自为政，无统一装配点、无统一开关、EXPLAIN 不可见（除
dispatch 行）。**O-1 的目标不是新语义，是把"计划级规则"收进框架。**

## 1. 规则框架（v1 形态：AST 上的 pass 序列）

```
optimize(stmt, ctx) -> (stmt', applied: Vec<&'static str>)
```

- **规则合同**（每条规则必须满足，评审即查）：
  1. **确定性**：同一输入恒同输出（无时间/随机源——expr.rs 无
     volatile 函数，v1 全量谓词确定性成立）；
  2. **语义保持**：改写前后结果等价（tests/common §1.1 正式定义）；
  3. **差分可枚举**：`SET dendro.optimize = 'on'|'off'`（调试面，同
     force_source 约定）可关停单条或全部——off = 原路径；
  4. **可见性**：EXPLAIN 输出 applied 规则名（人可审）。
- v1 的"计划"= sqlparser AST + eval_select 装配上下文（表因子序/
  各因子可用列）。逻辑计划 IR（02 号 spec 的 Plan 结构）是 v2 的
  迁移目标，AST pass 的接口按"可平移到 Plan 重写"设计（规则只依赖
  `表因子集合 + 各因子列名空间`，不依赖 AST 内部形态的细节）。

## 2. O-1 规则集

### R1 谓词合取拆分（conjunct splitting）

`WHERE a AND b AND c` → `[a, b, c]`（穿透 Nested；OR 不拆——
析取保持原子性）。

### R2 合取下推（single-source conjunct pushdown）

- **分类**：对每个合取项收集标识符集合；项内**所有**标识符均为
  限定名（`alias.col` / `table.col`）且前缀同一表因子 → 该因子的
  下推项。
- **保守边界**（v1 明确不下推的形态，结果仍正确——只是留在
  join 后过滤）：
  - 裸列名（无前缀）：多因子下歧义，v1 不做消解；
  - 引用 ≥2 个因子的合取项（跨表谓词）；
  - OR 析取、子查询谓词（v1 无子查询求值面）。
- **应用点**：eval_from 内各因子 table_scan_opt 之后、join 之前，
  对该因子 TableView 附加过滤（复用 WHERE 的 FilterOp 管线路径）。
- **语义安全论证**：
  - 下推是**加性**的——join 后的 WHERE 原样保留；
  - INNER JOIN：双侧预过滤 + join + 原过滤 ≡ 原路径（σ 下推是
    关系代数恒等式 σ_p(A ⋈ B) = σ_p(A) ⋈ B，p 只引用 A 列时）；
  - **LEFT JOIN 右侧下推**：σ_p(R) 预过滤后，本不匹配的左行变为
    NULL 扩展行——但 join 后保留的 p(R.col)=NULL 判非真仍被过滤，
    与原路径"全量 R + 事后过滤"结果一致（NULL 扩展行两侧都活不到
    输出）。前提：p 确定性（§1 合同 1）。
  - 列名消解：因子内 tv.names 为裸列名；限定名 `o.x` 经 col_lookup
    的限定名回退（scan.rs:756）匹配裸 `x`——与 join 后过滤同口径。

### R3 表达式简化扩展（既有 R-expr 的增量）

- NOT 消除：`NOT NOT x → x`；`NOT TRUE/FALSE` 折叠（原 fold_bool
  只处理 AND/OR）。
- 其余（x=x 恒真等）v1 **不做**：NULL 语义下 `x = x` 非
  恒真（NULL → NULL）——需要 not-null 参数，记 v2。

## 4. 路线（O-2+）

- **O-2 计划 IR 化**：AST pass → 02 号 spec 的逻辑 Plan 重写（规则
  平移：分类依赖的"因子+列名空间"即 Plan 的 Scan 节点）；dendro.ir
  文本形态输出优化前后计划（diff 审阅面）。
- **O-3 投影裁剪**：列使用分析 → Scan 投影下推（需列存投影扫描
  接口）。
- **O-4 代价**：行数估计（manifest row_count/col_rows）驱动 join
  顺序；v1 固定左深。
- **O-5 top-N**：SortOp 有界堆（LIMIT + ORDER BY 的内存上界）。

## 5. 实现前必须回答

1. 下推项在因子过滤时报错（类型错配）的语义：因子级报错 vs join 后
   报错——原路径在 join 后报。**加性下推可能提前报错**（对不进
   join 的行）。v1 取提前报（fail-loud，错误码一致即可，行集差异
   仅在错误路径——记 known-delta）。
2. 多层嵌套 join 的因子序：v1 只处理 FROM 首因子 + 一层 JOIN 链
   （eval_from 现状），嵌套 join 表达式 not_supported（既有）。
