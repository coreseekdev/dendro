# 09 文本表示（LLVM/MLIR 式）

> 补充要求（评审意见）：IR 必须具备**纯文本表示**——同 LLVM 的 .ll、
> MLIR 的自定义汇编。文本形式是一等性质，不是 EXPLAIN 的附属品。
> 三条性质合同：**P1 round-trip**（parse(print(x)) ≡ x）、
> **P2 确定性**（同一计划恒同字节）、**P3 人可读可审阅**。

## 1. 用途（决定格式要求）

| 用途 | 要求来源 |
|------|---------|
| PR diff 审阅（计划变更肉眼可查）| P3 |
| **golden 文件测试**（语料计划 dump 成 `.ir` 入库，破坏即 diff）| P2——字节级确定 |
| EXPLAIN 输出 | P3 + 派发注解（§5）|
| round-trip 测试（proptest：任意计划 → 文本 → parse → 结构全等）| P1 |
| 跨进程/跨语言检视（agent 场景外部读计划）| P1 + 版本化 |
| prepared 语句持久化（远期）| P1 |

**不追求**：文本形态的执行性能（执行永远走内存结构）；作为对外稳定
API（版本锁死前不承诺外部兼容；外部交换若需要走 Substrait，见 SOTA
调研观察旗）。

## 2. 语法骨架（dendro.ir v1）

MLIR 风格：显式 SSA 名、每行一操作、`;` 注释、`{}` 属性块。

```text
dendro.ir v1
plan {
  %t0 = table "public.t" {cols = 3, pk = [0]}
  %c0 = const i64 10
  %s0 = scan %t0
  ! snapshot = 1726400000000          ; 执行上下文以注解呈现（评审 P2：
  ! txn_head = none                   ; 快照随执行变化，不入 IR 本体——
  %f0 = filter %s0, @pred_main        ; 否则 golden 跨运行必 diff）
  %p0 = project %f0 {cols = [0, 1]}
  yield %p0
}

scalar @pred_main {                       ; 标量方言（03 号 spec 的步列表）
  %v0 = col 1
  %v1 = const i64 10
  %v2 = cmp.gt %v0, %v1
  ret %v2
}
```

约定：
- **SSA 名**：`%t/%s/%f/%p/%c`（表/扫描/过滤/投影/常量）、标量内 `%v`；
  顺序分配，printer 保证与构造序一致（P2）；
- **标量方言内基本块**：跳转目标用标签 `L0:`（文本层用标签，内存层是
  步索引——printer/parser 负责换算，LLVM basic block 同法）；
- 类型显式：const 带类型后缀（`i64 10` / `f64 0x3ff8...`（bit 表示，
  P2 要求 NaN/Inf 确定性）/ `str "..."`（转义规则 = JSON 字符串转义）/
  `null`）；
- ScanAlt 候选集**不入文本**（那是派发器产物，非逻辑 IR）——物理选择
  以注解形式出现在 EXPLAIN（§5）。

## 3. 确定性规则（P2 的实现合同）

1. 属性按**固定顺序**打印（构造顺序无关）；
2. 浮点用 IEEE754 位模式十六进制（`0x` 前缀）——禁用十进制往返；
3. 常量池按首次引用序编号；
4. 集合类属性按**构造序**打印（评审 P2：组序首见序有语义，按值排序
   会破坏 round-trip——P1 与 P2-规则4 冲突已修）；
5. 无时间戳/地址/指针值进入文本——**任何非确定性内容禁止入 IR**；
   snapshot/txn_head 等执行期上下文以 `!` 注解呈现，不入 IR 本体；
6. 常量类型标签完整集：i32/i64/f64/bool/str/bytes(hex)/date32/
   timestamp_ms/null（示例补 i32/bool——评审 P2）。

## 4. 版本化与校验

- 首行版本号 `dendro.ir v1`：parser 拒绝未知版本与未知操作
  （**fail-closed**，不做尽力解析——MLIR 教训：宽容解析会积累不可
  迁移的语料）；
- **verifier**（MLIR 同款思想）：parse 时与构造时共用一套校验——
  Col 索引 < 绑定列数、Jump 目标落在块内、类型匹配（Cmp 两操作数
  同 Ty）等；非法结构在构造期即被拒，而不是等执行期炸；
- IR 版本升级 = 新版本号 + 迁移器；golden 文件带版本头，升级时
  机械重生成。

## 5. 与 EXPLAIN 的关系

EXPLAIN = 文本 IR（逻辑 + 标量）**加注**物理派发信息，注解以 `!` 前缀
（区别于 IR 本体）：

```text
%s0 = scan %t0 {snapshot = ...}
  ! dispatch: MainPlusDelta segs=3/7 pruned=4 tail=yes (rule#4)
  ! [forced: delta]                          ; 仅调试构建
```

这样 EXPLAIN 的 IR 部分可 round-trip（粘给复现 bug 的用户，parse 回来
即是当时的逻辑计划），注解部分仅供人读。

## 5.5 printer 细节（评审 O6/D7 补）

- 每算子输出**稳定短 id**（`%s0` 等，SSA 名即 id）——diff hunk 可定位
  （DuckDB graphviz node_0_0 同动机）；
- **golden 双轨**（DuckDB slt 实践）：字节级全量 golden（语义变更 PR
  用，人工审阅 diff）+ 正则锚定 smoke（防格式噪声）；
- `!` 注解通道扩展承载执行期注解：派发信息、快照、**EXPLAIN ANALYZE
  的 rows/time**（来自 04 §2 metrics 挂点）。

## 6. 测试

| 测试 | 性质合同 |
|------|---------|
| proptest：任意合法计划（受限形状生成器）→ print → parse → 结构全等 | P1 |
| 确定性：同一计划 print 两次字节全等 | P2 |
| **golden 文件**：测试语料每查询的 `.ir` 入库（tests/golden/）；语义改动的 PR 中 diff 即计划变更审阅面 | P2/P3 |
| verifier 负测试：构造非法计划（坏跳转/类型错配）→ 构造期报错 | §4 |
| **差分联动**（07）：force_source 各路径的 golden `.ir` 不同、结果全等——计划可见地不同而结果等价，即派发正确性的可读证据 | 联动 ADR-5 |

## 7. 实现位置与范围

- `crates/dendro-core/src/ir/text.rs`（printer+parser+verifier 同文件，
  防漂移）；ScalarProgram 的文本形式在 `sql/` 侧步列表模块同构实现；
- **范围**：v2b 覆盖标量方言（B4 的 EXPLAIN 步列表直接升级为本文格式）；
  逻辑方言随 v2c-1（C4 的 EXPLAIN）落地；
- **不做**：二进制序列化（内存结构直转文本足够；二进制留给 Substrait
  场景）、IR 级宏/attach 元数据等 MLIR 高级特性。

## 8. 实现前必须回答

1. proptest 的"任意合法计划"生成器边界：算子深度、谓词步数上限？
   （建议：深度 ≤6、步数 ≤64，覆盖 Jump/Label 组合即可。）
2. golden 文件的更新纪律：语义改动的 PR 必须同步重生成并**人工审阅
   diff**——写进 CONTRIBUTING/AGENTS 检查单？
3. 字符串转义采用 JSON 规则是否与现有 Utf8 内容（任意字节序列）兼容？
   非 UTF-8 Bytes 列建议 hex 表示（`bytes 0x...`）。
