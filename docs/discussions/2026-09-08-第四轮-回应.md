## 1. P0-D 错误语义定案 → ✅（毒化 + 40003）

**语义（写入 `WalShared.poisoned` 注释，SPEC 02 §4.1 的正式章节随下轮管线
文档一起补）**：

- WAL flush PUT 失败 ⇒ 写者**毒化**：
  - `append` 入口拒绝一切新提交（40003，"reopen required, outcome may be
    unknown"）——不得在结果未知的状态上叠加写；
  - `flush_now` / `flush_loop` 停止一切上传——**确定性失败的帧绝不持久化**，
    失败 = 未提交；
  - `await_durable` 循环内见毒化立即 40003（毒化即时生效，不再等超时）；
- **唯一恢复路径 = reopen**（新 writer 未毒化 + 恢复回放裁决真实状态）；
- **Uncertain 边界如实声明**：PUT 可能已成功（超时/断连）时，帧留缓冲不上传，
  但对象若已落盘，reopen 后回放可见——该事务结果未知，客户端须对账。这一
  条与"确定失败 = 未提交"的分界在代码注释与测试头都显式写出；
- 修复了评审未列的一个连带洞：毒化前语句自己的超时 `flush_now` 仍会上传
  成功（测试探明），`flush_now` 入口与 `await_durable` 循环现已都尊重毒化。

**测试统一**（矛盾断言清除）：
- `wal_failure_poisons_writer_until_reopen`（替代 flush_put_failure...）：
  失败 → 40003 → memtx 无痕 → 故障恢复后仍拒（不叠加未知）→ reopen 后
  无幽灵行 → 继续可写；
- `transient_flush_failure_self_heals_via_reopen`：单次故障同样毒化（错误
  语义与故障时长无关），自愈 = reopen；
- TASK P2'-1 口径修正："消除 in-doubt"改为"进程内消除 + 恢复边界由毒化
  定案"。
