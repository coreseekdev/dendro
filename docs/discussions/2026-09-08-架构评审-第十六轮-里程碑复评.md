## 2. R16-1（P1）：Q-12 回归空转——变异 3/3 绿，NoWait 探针红/绿闭合

**这是 R13-1（q14 空转）的同类再现，本轮核心发现。**

- **根因**：测试用 `opts_store`（`wal_corruption.rs:18-21`），其中 `durability: Durability::Group` 硬编码。Group 提交经 `await_durable`（`wal.rs:389`）**在 `exec` 返回前已上传**——`close_graceful`（:476）被调用时缓冲必空，`flush_now` 必为 no-op。测试注释"NoWait 语义下假设缓冲未及上传"（:474）与事实相反：测试根本不在 NoWait 下运行。
- **变异 M1（评审人实跑）**：`close_graceful` 的 flush 整体移除（退化为 `close()`）→ 测试 **PASS，3/3 次**（0.03s）——回归对其声称守护的行为**零灵敏度**。
- **探针 R16-P1（评审人实跑，已还原）**：仅把测试的 durability 改为 `NoWait`（其余不动）：
  - 正确实现下 → **PASS**（NoWait 尾经 close_graceful 持久，重开可见）；
  - 同一变异 M2（flush 移除）下 → **FAIL**（尾丢失，count=0）。
- **结论**：修复本身工作正常（探针 A 验真），一行改动即可使回归真实（探针 B 验证红/绿闭合）；但在修复落地前，Q-12 按 DoD 属"代码变更 ✓ / 文档同步 ✓ / **回归测试 ✗**"——G3 不因本轮上调，Q-12 的 ✅ 记账应视为**带缺陷交付**。
- **模式警示**：R13-1（AP 路径短路）与本条（持久级短路）的共同根因是**回归没有钉住修复的前提条件**。q14 的教训曾以"col_rows≥1 万门断言"收口——本条同款收口即"持久级必须显式 NoWait"。建议 **DoD 增补第 7 条：行为级新修复的回归必须附变异自检记录（禁用修复 → 红），写入 TASK.md 证据列**，把第十三轮以来的临时做法制度化，终结这类"第三轮才被发现"的空转。
