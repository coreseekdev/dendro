## 2. 本轮发现（按严重度）

### 2.1 R21-1（P1）LIMIT 下推 × 聚合/GROUP BY/HAVING = 静默错误结果

`scan.rs:74-92` 的下推门只检查 `select.selection.is_some() || has_join`，**未检查聚合投影 / GROUP BY / HAVING**；`eval_from`（:93）随即按 limit 截断扫描（行路径 `:990-998` 解码循环 break），聚合在**截断后的视图**上计算（:121-171）。

评审人探针（100 行表）：

| 语句 | 实际 | 应为 |
|---|---|---|
| `SELECT count(*) FROM t LIMIT 1` | **1** | 100 |
| `SELECT max(id) FROM t LIMIT 1` | **1** | 100 |
| `SELECT count(*) FROM t LIMIT 50` | **50** | 100 |
| `SELECT v, count(*) FROM t GROUP BY v LIMIT 3` | 按 3 行分组 | 按全量分组 |

AP 路径**同样中招且更隐蔽**：cap 只在归并分支生效（`scan.rs:602-607` 位于 `if !overlay.is_empty() || txn_has_writes` 内）——12,001 行表无 overlay 时 `count(*) LIMIT 1` 碰巧正确（12000，early-stop 实际失效）；**checkpoint 后改一行（overlay 非空）立即变 1**。即：同一语句在表的生命周期不同阶段给出不同答案。

这与 R18-1（先截断后过滤静默漏行）同类——下推门每漏一个维度就复发一次。修复小：`has_agg`/group_exprs 非空/having 非空 的判定（现 :121-126 在扫描后）上提到门条件即可；顺带把 AP/行路径的 cap 口径统一（无 overlay 分支也 cap，或明示不早停）。**回归 + 变异按 DoD 第 7 条**。

### 2.2 R21-2（P1）Q-16 修复误伤：事务内 DELETE 后重插同键 → 虚假 23505

`ddl.rs:413`：`txn.writes.contains_key(&(table_id, key))` **不区分 Put/Delete**。评审人探针：

```
BEGIN; DELETE FROM t WHERE id = 1; INSERT INTO t VALUES (1, 'new') → 23505
"duplicate key value violates primary key constraint (key already inserted in this transaction)"
```

PG 允许该序列（delete-then-reinsert 是搬移/upsert 类应用的常见形态）；INSERT;DELETE;INSERT 同样被误拒。仅当写集中既有条目为 `Mutation::Put` 时才应拒绝；Delete 条目应被新 Put 覆盖。注：UPDATE 路径不经此检查（slt 012 事务内 UPDATE 正常），故影响面为显式 DELETE+INSERT 序列。这是本批 Q-16 修复（`3b97104`）**新引入的回归**——新键重复 INSERT 的正确拒绝（M-R21-1 变异证实）与误伤需同批修掉。

### 2.3 R21-3（P2）M-5 flush 延迟计数器死接线——指标恒 0，采集的数据被丢弃

commit `a0218ce` 声称 "latency counters for commit/flush/manifest exposed via /metrics"。事实：真实采集在 `wal.rs:13-14` 静态量（`flush_now` 计时含 PUT 上传，`:478-479` 自增），而 `metrics.rs:131` 读取的是 `db.lat_flush_cnt/lat_flush_sum_us`（`engine.rs:360-362,455-457`）——**全仓 grep 无任何对后者的自增点**。/metrics 永远输出 `dendro_wal_flush_count 0 / sum_us 0`，wal.rs 采到的真数据无人消费。修复一行级（metrics 改读 statics，或由 Database 持有引用回写）。顺带观察：`lat_commit` 实测段仅为 `wal.append`（commit_tx 内，`engine.rs:1339`），`dendro_txn_commit` 命名偏宽（validate/install 未计入）——无伤大雅，建议注释注明口径。

### 2.4 R21-4（P2）常量短路定位错误——"免全表遍历+行解码"声称不成立，且无性能证据

`scan.rs:93` 的 `eval_from`（全表遍历 + 逐行 `row_from_bytes` 解码）在 `:99` 常量判定**之前**执行；`WHERE 1=0` 返回空集时，遍历与解码成本已全部付出，实际省下的只有 `:111-117` 的逐行过滤循环。注释（:96-98）"跳过扫描直接返回空集（免全表遍历+行解码）"与实现相反。修复：把 `!has_column_ref(w)` 判定与常量求值上提到 `eval_from` 之前（当前正确性前提——未解析列报错回退——不受影响）。另：该特性没有任何 bench 前后数字（无证据链），013 的短路回归对"删掉短路"不敏感（行为不变），DoD 第 7 条对纯性能特性结构性失明——**建议 DoD 补一句：性能类交付以 bench 数字为回归证据**（与 G7 纪律一致）。
