## 2. 本轮新发现（按严重度）

### 2.1 R21-13（P1）自引用视图 → 栈溢出 SIGABRT，进程崩溃

`sql/mod.rs:542-554` CREATE VIEW **不做任何体校验**（不解析执行、不检查环、不检查表/视图存在性），`scan.rs:459-471` 展开时递归 `eval_query` 且**无深度上限**。评审人崩溃探针（独立测试进程）：

```
CREATE VIEW rv AS SELECT * FROM rv;   → 成功（42P07 只查 views 自身，无环检测）
SELECT * FROM rv;                      → has overflowed its stack / fatal runtime error:
                                         stack overflow, aborting（SIGABRT，进程终止）
```

服务器场景下这是**任一会话用两条语句杀死共享实例**（全部连接掉线、k8s 下触发重启循环）。根因是"CREATE 不校验、SELECT 才爆"模式——同模式下界（错误而非崩溃）见 R21-14。修复小：CREATE 时对 query 体做一次展开验证（环 → 42P07/4271 类错误）+ 展开深度上限（如 16 层）双防线；回归 + 变异按 DoD 第 7 条。

### 2.2 R21-14（P2）视图无命名空间守卫：可遮蔽基表；无 FROM 体创建即不可查询

探针 P-I5：基表 `shadow` 存在且含数据 → `CREATE VIEW shadow AS SELECT 42 AS id` **成功**（PG 应 42P07 relation already exists；实现只查 `m.views` 不查 catalog 表命名空间，`sql/mod.rs:545`）→ 此后 `SELECT * FROM shadow` 命中视图展开路径，**基表永久不可达**（直到 DROP VIEW）。叠加"无校验"根因：无 FROM 体（`SELECT 42 AS id`）创建成功、查询时报 `42601 missing FROM`（`scan.rs:392`）——本仓 SQL 面整体不支持无 FROM SELECT，但 CREATE 端照单全收。注：本批自身回归 `views_create_select_drop` 里 `CREATE VIEW v_dup AS SELECT 1` 正是创建了一个不可查询的视图而未被察觉。修复：CREATE VIEW 校验表/视图命名空间冲突 + 体可执行。

### 2.3 R21-15（P2）视图大小写口径分裂：MixedCase 视图创建即永久不可用

存储用原文名（`sql/mod.rs:544` `join(".")` 不折叠），查找折叠小写（`scan.rs:462` `to_ascii_lowercase`），DROP 又用原名（`:558-559` `contains_key(&name)` 不折叠）。探针 P-C：`CREATE VIEW Foo` 成功 → `SELECT * FROM Foo` **42P01**、`SELECT * FROM foo` **42P01**、`DROP VIEW Foo` 成功。即大写/混合大小写视图处于"建得成、查不了、删得掉"的陷阱态；与游标名（DECLARE/FETCH 双端都折叠小写，`sql/mod.rs:995,1013`）的口径也不一致。修复一行级：两端统一折叠（与游标对齐）。

### 2.4 R21-16（P2）事务内 CREATE VIEW 绕过 Q-10 守卫，ROLLBACK 不撤销

`is_ddl`（`sql/mod.rs:430-439`）不含 `Statement::CreateView`。探针 P-F：`BEGIN; CREATE VIEW tv...; ROLLBACK` → CREATE 被接受、**ROLLBACK 后 tv 仍存在**（catalog 写立即发布、不入事务写集——Q-10/R20-1 同类漏洞在视图上的复现）；而 `DROP VIEW` 在事务内被 `Statement::Drop { .. }` 正确拦截 25001——**同族语句一进一出的口径分裂**。修一行：is_ddl 加 `Statement::CreateView { .. }`（v2 catalog 事务化时一并放开）。

### 2.5 R21-17（P2）`SELECT DISTINCT` 投影静默忽略——静默错结果

探针 P-N：100 行表 v 仅 10 种取值，`SELECT DISTINCT v FROM t` 返回 **100 行**（去重未发生、也无 0A000 报错）。全仓仅 `COUNT(DISTINCT x)` 聚合参数形态有实现（`scan.rs:1325` `fn_distinct`），投影级 DISTINCT 解析接受、语义未实现、**无任何报错**——静默错结果类（与 R18-1/R21-1 同族：语法黑洞比显式 not_supported 更危险）。顺带：LIMIT 下推门也无 DISTINCT 维度（现无实害，实现 DISTINCT 时须补门）。修复：先显式 `0A000 not supported`（分钟级），实现去重后撤守卫。
