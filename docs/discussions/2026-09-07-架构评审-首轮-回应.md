## 1. 逐条回应

### §5.1 WAL flush 失败丢帧 + 挂死

**确认**。`flush_now` 中 `mem::take(buf)` 后 PUT 失败，缓冲已清空 → 帧丢失。且 `flush_loop` 仅 log 不重试，`durable_seq` 永不推进 → `await_durable` 永久挂起。
**修复方案**：PUT 失败时把帧回退到缓冲头部（保留原 seq 偏移），下次 flush 重试；`flush_loop` 对 PUT 失败做指数退避重试。

### §5.2 恢复路径 panic

**确认**。`decode_row` 对截断行 `r[..4]` 直接 panic（无长度守卫）；`FrameIter` 对坏 len 无守卫。
**修复方案**：所有 `try_into().unwrap()` 改为返回 `Err`；`FrameIter` 在 `off + HEADER_LEN > data.len()` 时返回 `None`（而非 panic）。补坏帧/截断段构造测试。

### §4 P1 fencing 语义夸大

**确认**。三处文档声称的"运行时拒写/TTL 门控/续期"均未实现。`commit_tx` 无租约校验，`renew()` 零调用，接管不等待 TTL。
**修复方案**：
- 短期：修改 `multi_node.rs` 测试头注释 + 设计文档措辞（"epoch 路径隔离 + 恢复期抑制"而非"运行时互斥"）
- 中期：实现 `commit_tx` 前的租约过期检查 + `renew` 续期线程

### §2 共识选型自相矛盾

**确认**。正文论证"不从 Raft 库开始"，末尾追加"锁定 raft-rs"且未修订正文。
**修复方案**：在 `共识实现选型.md` 中补一段"决策理由"：用户决策选择了 raft-rs 作为 Journal 底座，跳过 M2 自研 Quorum Append 阶段（与 Aurora DSQL 选择商业级 Journal 的理由一致：减少自研协议的维护负担）；同时如实标注 `journal.rs` 当前状态为骨架（Ready entries 未持久化）。

### §1.2 A1 向量化执行器

**确认**。v1 执行器是行式解释器（`Vec<Vec<SqlValue>>` 物化），不是向量化列式。
**修复方案**：修订 SPEC 00 §2 和 G4 措辞——v1 = 行式解释器 + 列存投影；向量化列式执行器列入 v2 任务。

### §1.3 SQL 语义缺陷 S1–S6

**全部确认**。逐项修复：
- S1 WHERE 吞错 → `Ok(x) if x != Bool(true)` → 保留行，否则报错
- S2 failed_txn → 在 exec_statement 错误时设置 `sess.failed_txn = true`
- S3 join 键碰撞 → 加类型 tag 到归一化键
- S4 Int32 溢出 → checked_add + 溢出报 22003
- S5 单 INSERT 重复 pk → 在 exec_insert 的行循环内检测 txn 写集重复
- S6 WITH 静默丢弃 → 返回 0A000

### §1.2 A6 无 GC

**确认**。`ManifestStore::retained()` 是死代码，`replay_branch` 全历史回放。GC 列为 P1（评审优先级）——设计已有，实现缺失。

### §1.2 A7 只读打开

**确认**。`branch()` 对纯读也领 epoch + 启动 WAL writer 线程。修复：`Database::open` 增加 `read_only: bool` 选项；read_only 时跳过 fence acquire 和 WalWriter 创建。
