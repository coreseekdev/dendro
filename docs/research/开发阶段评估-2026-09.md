## 2. 分层实现状态

### 2.1 存储/事务内核（定案级 ★★★★★）

- **prolly tree 内容寻址 + CAS**：追加式、全历史可查、chunk 级 diff；
- **WAL**：group-commit 三档持久性、epoch 入路径 fencing（租约 CAS +
  运行时 40001 拒写 + 写后校验 + 自毒化终态）、段退休安全界（TLC 验证）、
  毒化语义、撕裂尾容忍；
- **事务**：memtx OCC（SI 型合同成文）、两段式提交（裁决/安装分离，
  Adjudicator/Journal seam 预留多节点）、fence/acquire 竞争窗口防护；
- **manifest**：编号版本 + put_if_absent CAS + putid 不确定性消解 +
  LIST 权威（与 Lance 互证）+ 条件写开工自检；
- **GC**：墓碑随版本原子发布 + retention 窗口 + 围栏对象回收规则成文；
- **恢复**：epoch 升序 + ts 抑制回放，前缀性/可重建性断言 + 重开等价回归。

### 2.2 SQL 面（核心可用 ★★★☆，两周内从 ★★ 提升）

差异评估（2026-09-16 前）列的 **P0 生产硬门槛已全部清账**：

| 当时 P0 项 | 现状 |
|-----------|------|
| 窗口函数 8 种 + OVER(PARTITION/ORDER) | ✅ 033_window.slt + Plan::Window + 计划方言 |
| CTE（非递归 + 递归） | ✅ Plan::Cte/IterativeScan（delta 工作集不动点，PG 语义） |
| 标量/IN/EXISTS 子查询 | ✅ 且超出计划：SemiJoin 下沉 + **相关子查询迭代求值**（memo + 嵌套/派生表穿透） |
| UPSERT | ✅ ON CONFLICT DO NOTHING/DO UPDATE + excluded |
| CHECK | ✅ 语句级守卫 + 目录级缓存 |
| UNIQUE | ✅ 单语句批量键集 |
| 外键 | ✅ v1（REFERENCES → 父表 PK） |

另已具备：DISTINCT、集合操作三算子、视图（+解析缓存）、GRANT/REVOKE、
游标、版本查询（FOR SYSTEM_TIME AS OF）、MERGE BRANCH（行级冲突）、
EXPLAIN/ANALYZE 统一计划方言。**架构面**：AST 求值路径已退役，
单一计划路径（11 文件 scan 模块，最大 1,213 行），dendro.ir v1
可打印可回 parse。

剩余缺口（现 P2 级广度项）：JSON/数组/触发器/存储过程/FTS/ENUM、
在线 DDL 仅 ADD COLUMN、UPDATE/DELETE 谓词不含子查询。

### 2.3 AP/列存（原型后期 ★★★★）

CBF 64B GPU 对齐 + 六 codec + 编码选举四重奏（确定性成律——内容寻址
前提）+ zone map 剪枝 + 稀疏读（掩码扫描 get_range）+ 段统计接入
EXPLAIN est。缺：并行扫描、SIMD 内核、直方图、字典 int 优化已并入
RLE_DICT、FFOR 族未做（JIT 立项时合批）。

### 2.4 服务与运维（试用级 ★★★）

双协议（pgwire v3 / mywire）+ 认证 + /metrics /readyz + 优雅关闭 +
k8s yaml + backup 工具 + bench 面。缺：驱动生态（可复用 PG 驱动是
设计红利但未验证）、慢查询日志、在线 DDL 广度。

### 2.5 验证体系（领先 ★★★★★）

差分轴 + SLT + golden/round-trip + TLA+（模型检查 + 否定性验证）+
Kani 镜像 + 恢复不变量断言 + 设计评审 checklist + 账本文化。
本阶段评估即由此体系背书（"跑过的没坏，没跑到的也可论证"）。

## 3. 阶段判读

```
研究原型 ────●──────── 内核 MVP ──────── 产品化 ──── 生产就绪
            ▲ 当前位置（内核收敛完成）
```

- **已越过的门槛**：架构定案（六阶段 SQL 统一迁移完成、AST 路径退役）、
  正确性防线收敛（8 轮零 P0）、SQL 硬门槛清账、形式化验证接入；
- **尚未开始的门槛**：真实负载淬炼（无任何现场数据）、性能工程
  （并行/JIT/直方图全未做）、生态（驱动/文档/社区）、多节点（P2'/P3
  仅有 seam 设计）。

**单写者约束**是当前最重要的架构边界：每分支一写者 + fencing 使
并发扩展和多节点成为显式的后续阶段而非债务——这是设计选择，
评估时不算缺陷，但决定了试用形态（写单点、读可多副本）。

## 5. 下一阶段建议（按杠杆排序）

1. **真实负载试用**（最高杠杆）：内部/边缘场景接入真实查询流——
   验证体系的下一层证据只能来自现场；同时产出慢查询/est-actual
   差值的首批真实数据（喂给优化器迭代）；
2. **性能 P1 批**：并行扫描（S3 机会式派发语义框架已在调研成文）+
   直方图（ANALYZE + footer 统计已有骨架）+ bench_pair 评测纪律
   （qorl 调研 P0）；
3. **广度 P2 批**（按需求拉动，不预先铺开）：JSON → 数组 → 触发器；
4. **产品化最小面**：用户文档（从 design docs 提炼）+ PG 驱动兼容
   验证（psql/pgx 打通即生态零成本）；
5. 调研队列落地项照旧滚动（向量索引/Kani 对拍/谓词冲突位等已分级
   成文，不重复）。

### 7.2 复评结论

上一轮评估的判断全部维持；新增的唯一结构性变化是**度量与 CE 地基
已就位**（bench_pair + ANALYZE + 精确 NDV）——此后任何性能主张都有
纪律数字、任何 CE 改进都有前后对照。待办清单的形态从"补地基"转为
"等地基换产出"：P0 只剩真实负载（外部依赖）与用户文档，其余全部
降为可排期的 P1/P2。
