# 向量搜索库 SOTA 调研（2026，含 zvec）

> 调研时间：2026-09-18。触发：用户问询 SOTA 向量搜索库（点名 zvec）。
> 结论先行：
>
> 1. **zvec = 阿里通义的"向量数据库界 SQLite"**（Apache-2.0，C++ 内核
>    100+ 定制内核 + 官方 Rust 绑定）：in-process、稠密+稀疏+多向量、
>    混合检索（向量 + BM25 + 结构化过滤）、WAL 持久、多进程读/单写。
>    v0.7.0 把两条 2026 SOTA 路线**生产化**：DiskANN 磁盘图索引
>    （ARM64 + io_uring 异步 I/O 自动降级）与 IVF-RaBitQ（RaBitQ
>    量化 + AVX2/AVX512 运行时分派）。定位与 dendro 的嵌入库形态
>    最接近，但内核是 C++（FFI 集成成本）。
> 2. **算法面 SOTA 三件套**：RaBitQ（D 维 → D 比特量化，带理论误差
>    界——2024 论文已被 Elastic/LanceDB/VectorChord/Milvus 广泛采纳，
>    且有纯 Rust 实现 rabitq-rs）；DiskANN/Vamana 磁盘驻留图（原生
>    Rust 有 diskann-rs / rust-diskann）；SPANN 类簇路由。
> 3. **架构面对 dendro 最有参照系价值的是 Lance**（Rust 原生列存 +
>    不可变版本化分片 + 对象存储 serverless + 向量索引含 RaBitQ）——
>    与 dendro"内容寻址 + 追加式 + 对象存储"三约束同谱系。
> 4. **建议路线（对接《pgrust列存与向量索引调研》P2）**：dendro 不引
>    入 C++/服务型依赖，走**自建段级 IVF + RaBitQ 量化列**（量化码进
>    CBF 段 = 内容寻址天然成立；纯 Rust 参考实现齐全：rabitq-rs +
>    diskann-rs 可作对照实现）；嵌入式整库引入（zvec/usearch）仅作
>    差分基准，不作依赖。

## 1. zvec 深读（用户点名）

| 维度 | 事实 |
|------|------|
| 出品 | 阿里巴巴通义实验室；内核 = 内部向量引擎 **Proxima** 的抽取重写；C++ 核心（100+ 针对硬件定制的内核）+ 官方 Python/Node/Go/**Rust**/Dart SDK |
| 定位 | 轻量进程内向量数据库（"the SQLite of vector databases"）——装好即用，面向边缘/端侧 RAG 与服务嵌入 |
| License | Apache-2.0（可集成） |
| 数据模型 | 稠密 + 稀疏（SPLADE 等生成）+ 多向量（ColBERT 风格 late-interaction）；标量过滤（>/</=/范围，路由过滤） |
| 检索 | 混合：向量 + BM25（v0.7 N-gram 分词器）+ 结构化过滤融合；DocIterator 流式 API（边检边取，别家少见的嵌入库流式面） |
| 持久 | **WAL**；多进程并发读 + 单写者 |
| v0.7.0 要点 | DiskANN 生产化（ARM64；**io_uring 异步 I/O，失败自动降级**）；**IVF-RaBitQ** 索引 + PQ-INT8 量化器（RaBitQ 运行时按 CPU 能力分派 AVX2/AVX512） |
| 生态位 | zvec-grep（zg）CLI：ripgrep + BM25 + 向量语义统一检索（RAG 版 ripgrep） |

**对 dendro 的镜鉴**：zvec 证明了"嵌入式向量库 + WAL + 磁盘索引 +
混合检索"四合一在工程上成立；其 v0.7 技术选型（DiskANN + RaBitQ +
io_uring）即当前业界对"磁盘、量化、异步 I/O"三问题的主流答案——
可作为 dendro 向量方向的技术雷达。

## 2. SOTA 全景（嵌入式库优先；服务型仅列对照）

| 库 | 语言/绑定 | 索引/量化 | 磁盘 | License | 备注 |
|----|----------|-----------|------|---------|------|
| **zvec** | C++ 内核 + 官方 Rust 绑定 | HNSW/IVF + RaBitQ/PQ-INT8 | DiskANN（io_uring） | Apache-2.0 | 嵌入式全功能；本调研 §1 |
| **usearch**（Unum） | C++ + Rust 扩展 | HNSW 变体（紧凑内存） | mmap | Apache-2.0 | 内存足迹小、快；绑定成熟 |
| **hnswlib** | C++ | 纯 HNSW 参考实现 | 否 | Apache-2.0 | ANN-Benchmarks 常青参照 |
| **FAISS**（Meta） | C++ + Python | 最全（IVF-PQ/SQ、GPU、混合） | 部分 | MIT | 功能最富但体量重、GPU 向 |
| **ScaNN**（Google） | C++ | 各向异性量化（SOTA 回忆/延迟之一） | 否 | Apache-2.0 | 研究 SOTA，工程活跃度低 |
| **Lance / LanceDB** | **Rust 原生** | IVF-PQ + **RaBitQ** | 是（不可变版本化分片，对象存储原生） | Apache-2.0 | **架构上与 dendro 最近**（列存+版本化+serverless）；RaBitQ 落地报告 ~80% 性能收益 |
| **diskann-rs / rust-diskann** | **Rust 原生** | Vamana 图 | 是 | 开源 | 原生 Rust DiskANN，成熟度低于 C++ 系 |
| **rabitq-rs** | **Rust 原生** | RaBitQ + IVF | 自理 | crates.io | 纯 Rust RaBitQ，自述生产可用 |
| Qdrant | Rust（**服务型**） | HNSW + 量化 | 是 | Apache-2.0 | 对照项：不嵌入 |
| Milvus / VectorChord | Go+C++ / Rust PG 扩展 | VectorChord 0.5 = **RaBitQ 驱动 DiskANN** | 是 | Apache-2.0 | VectorChord 是 PG 生态里"dendro 未来形态"的直接竞品 |
| Annoy | C++ | 树 | mmap | Apache-2.0 | 上一代，基本停更 |

基准面：[ANN-Benchmarks](https://ann-benchmarks.com/) 是召回/延迟
标准参照；2025-26 的 HNSW 实现对比研究（TechRxiv）覆盖
hnswlib/usearch/faiss-HNSW 三家。

## 3. 算法面 SOTA 速览

- **RaBitQ**（[arXiv 2405.12497](https://arxiv.org/abs/2405.12497)，
  2024，引用 237+）：随机化 D 维 → **D 比特**量化，带理论误差上界
  （优于朴素二值量化的硬估计）——1 比特/维存储下保留可校正的距离
  估计，重排用少量全精度分量。2025-26 被 Elastic、LanceDB、
  VectorChord、Milvus（对 TurboQuant 之争）密集采纳，**已是量化
  事实标准**。可读释文：Elastic 的
  [RaBitQ 101](https://www.elastic.co/search-labs/blog/rabitq-explainer-101)。
- **DiskANN / Vamana**：磁盘驻留图索引（SSD 随机读为主的贪心图
  构建 + 压缩全精度驻内存）。Azure HorizonDB 已生产化；SSD 图索引
  优化仍是 2026 活跃研究（[arXiv 2602.22805](https://arxiv.org/html/2602.22805v1)）。
- **SPANN**：簇质心路由 + 倒排 posting，内存驻路由、磁盘驻 posting
  ——与"段级剪枝"思路同构，dendro 列存段天然可映射。
- 混合/过滤检索：过滤策略分类学系统化（[arXiv 2602.11443](https://arxiv.org/html/2602.11443)，
  评测 FAISS/Milvus/pgvector）。

## 4. 对 dendro 的适配分析与建议

dendro 三约束：① 对象存储（S3，高延迟随机读昂贵）；② 内容寻址 +
追加式 + 分支；③ Rust 嵌入式单二进制。据此：

| 路线 | 评估 |
|------|------|
| 嵌入 zvec（FFI） | 功能最全但 C++ 内核 + 自带 WAL/存储层与 dendro 的 prolly/CBF/WAL 三层重叠——引入即第二存储栈，违背单一语义面（评审 checklist 9）。仅作**差分基准** |
| 嵌入 usearch | 轻（单索引、mmap），但 mmap × S3 不合；分支/内容寻址不可表达。同上仅基准 |
| **自建：段级 IVF + RaBitQ 量化列（推荐）** | 量化码 = CBF 段内普通列（内容寻址天然成立、分支共享免费）；质心 + 倒排表 = 独立 CAS chunk（epoch 分代，追加式合并）；查询 = 质心路由 → 段内 SIMD 扫描 RaBitQ 码 → 全精度重排（重排分量存低秩/抽样列）。纯 Rust 参考齐全：rabitq-rs（量化算术）+ diskann-rs（图构建对照） |
| 远期：DiskANN 风格图 | S3 随机读代价下图索引劣于段扫描 + 预取（机会式派发语义框架正好适用）；仅当单段内召回/延迟不足时在段内做图 |

与既有调研的衔接：本节即《pgrust列存与向量索引调研》P2 条目的
展开——pgvector 页式 HNSW 不可搬（堆/TID 模型），业界嵌入式 SOTA
（zvec v0.7 选型）与 dendro 约束的交集 = **RaBitQ + 段级路由**，
而非 HNSW。
