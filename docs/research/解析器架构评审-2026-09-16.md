# 解析器架构评审（2026-09-16）

> 2 agent 并行评审 + 差分实证。触发：子查询内联测试红——暴露了
> 管线级而非逐行 bug 级的架构缺口。

## 1. 管线现状图

```
SQL 文本 → parse_batch(mod.rs:61, 双方言 Pg/MySql)
  → exec_statement(mod.rs:596, 权限门 + DDL 事务门)
    → eval_query(scan.rs:92)
      ├─ [新] 子查询内联 → select + q 双 shadowing
      ├─ build_plan(q) → 6 rewrite passes → exec_plan
      │   (计划路径——~90% 形态)
      └─ eval_from → WHERE → agg → project → sort (AST 路径)
```

## 3. 窗口函数 / CTE / 外键最小实现路径（agent 2 产出）

### 窗口函数（止血 15 行 + 实现 ~300 行）
- **止血**：`eval_query` 入口加 `reject_window(q)` 预检——`sum() OVER()` 当前被当普通聚合 → 静默错误结果（全局聚合塌缩而非窗口展开）
- **实现**：WHERE 过滤后、GROUP BY 前，按 (partition, order) 排序分组算排名/裸聚合 → 结果追加为合成列 → 投影重写为 Identifier

### CTE / WITH（方案 A：AST 重写 ~150 行）
- `expand_ctes(q)` → 遍历 body FROM 把 `Table{cte名}` 替换为 `Derived{subquery: cte.query}`
- 接线：`eval_query` 入口 + 删 mod.rs:681 守卫；派生表/视图/INSERT..SELECT 自动获益
- v1 拒绝：recursive / materialized / 列别名

### 外键约束（~150 行）
- 解析：`TableConstraint::ForeignKey` → `ForeignKeyDef{columns, ref_table, ref_columns, on_delete}`
- 存储：`TableEntry.foreign_keys`（serde default）
- 执法：INSERT/UPDATE 检查父表存在（点查——限定 REFERENCES 必须指向父表 PK）；DELETE 反向查子表
- 顺带：NOT NULL 执法（6 行——nullable 字段全库无读点）

### 静默丢弃审计（10 项，按危害排序）
1. **`sum() OVER()` 当聚合**——最危险（窗口语义全丢）
2. 表级 FK/CHECK 静默丢弃
3. 列级 REFERENCES 静默丢弃
4. NOT NULL 不执法
5. 嵌套 WITH 绕过守卫
6. InSubquery 多列静默取首列
7. value_from_parser 未知字面量文本化
8. ExprWithAliases 按通配处理
9. ORDER BY 序数越界静默 NULL
10. CASE 内聚合不递归
